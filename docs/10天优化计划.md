## 5. 第 3 关“开门后过不去”的修复记录

### 现象

踩按钮、门开了，但门后面是一个 280 像素宽的坑，跳不过去。

### 真正原因（已用诊断脚本确认）

| # | Bug | 证据 | 修法 |
|---|---|---|---|
| 1 | 移动平台原点取错 | 平台实际在 x −60~60、y 0，设计位置是 x 910~1310 | `setup()` 里补 `_origin = global_position` |
| 2 | 行程被减半两次 | 实际行程只有设计值的 1/4 | `setup()` 里 `offset = off`，不再乘 0.5 |
| 3 | 渡船高度卡头 | 顶面 829，比地面高 51，和门前区域重叠，变成一堵墙 | 降到 y=891（顶面 880，和地面齐平） |
| 4 | 按钮物理回调改碰撞 | 每次踩按钮报 `Can't change this state while flushing queries` | `col.set_deferred("shape", shape)` |

### 修完后的预期

- 渡船在坑里左右往返，**和地面齐平**，走上去就行，不用跳；
- 站台 → 高台 → 电梯 → 终点，按正常跳跃就能过；
- `关卡检查.bat` 不再误报。

> 这一条会写进 AI 使用声明：**“AI 生成的移动平台代码有原点/行程 bug，是我用诊断脚本抓出来的。”**
> 这比“AI 一次写对”更真实，也是比赛想看的“人怎么验证 AI”。

## 6. 元素系统（A 方案）

### 6.1 核心规则（照你图里的想法）

1. 玩家一次只能拿 **1 个**元素；
2. 拿到后，走到对应的“接收器/障碍”旁边，**自动消耗**；
3. 消耗后手里空了，才能拿下一个；
4. 水会清空手里的火；冰可以把水冻成平台；火可以融冰；风给你一段跳远加速。

> 不做“按 E 使用”的按键：对零基础来说，**碰到就自动用**最不容易出错；
> 规则仍然是“一次一个、用了才能拿新的”。

### 6.2 四个元素的实现范围

| 元素 | 10 天版 | 具体交互 | 复用 |
|---|---|---|---|
| **火** | ✅ | 捡起火种 → 烧冰墙 / 放火盆开门 | 按钮→门 的信号 |
| **水** | ✅ | 走进水幕 → 手里的火被清空 | 玩家状态 + Area2D |
| **冰** | ✅ | 对水池使用冰 → 水面冻成桥 | 闪烁平台“实体/禁用” |
| **风** | ✅（第 5 关） | 风区给水平加速，跳得更远 | Area2D + 速度修正 |
| 雷 | 🟡 设计稿 | 激活移动平台/装置 | 移动平台开关 |
| 草 | 🟡 设计稿 | 生长平台/藤蔓 | 类似冰 |
| 石 | 🟡 设计稿 | 推箱子/重力机关 | 工作量最大，放最后 |

### 6.3 七个元素的完整设计（写进说明文档，不要求全做）

| 元素 | 玩法 | 和谁反应 |
|---|---|---|
| 冰 | 造台阶/通路；碎冰轻踩不破、重落/起跳破；坚冰由水转化，只有火能消 | 水、火 |
| 水 | 配合冰造路；灭火；进入时清空火 | 冰、火 |
| 火 | 破坏冰障碍；烧藤蔓；被水消灭；蒸发反应 | 冰、水、草 |
| 雷 | 激活装置；驱动移动平台；物理冲击 | 机关 |
| 草 | 植物生长成平台/藤蔓 | 火 |
| 风 | 提供移速/远跳；吹动实体；扩散火 | 火、石 |
| 石 | 障碍/台阶；重力机关 | 风、雷 |

### 6.4 代码结构（我会写的文件）

```
scripts/elements/
├─ element.gd            元素枚举 + 名字 + 颜色（唯一数据源）
├─ element_orb.gd        地上的元素球：碰到就捡
├─ element_receiver.gd   接收器：手里元素对得上就消耗、发信号
├─ water_zone.gd         水幕/水池：进入清空火
├─ ice_barrier.gd        冰墙：被火融化
└─ freeze_pool.gd        水池：被冰冻成桥

scenes/elements/
├─ element_orb.tscn
├─ element_receiver.tscn
├─ water_zone.tscn
├─ ice_barrier.tscn
└─ freeze_pool.tscn
```

玩家侧只加 4 个方法：`pick_up(kind)` / `consume()` / `clear_element()` / `has_element(kind)`，
再加一个“头顶的小元素球”显示。

信号（加在 `Events` 里）：
`element_picked` / `element_used` / `element_cleared` / `element_changed`

### 6.5 第 4 关「火种」（约 40 秒）

```
起点 ── 火种① ── 水幕 ── 火种② ── 冰墙 ── 火种③ ── 火盆门 ── 终点
        (捡)     (火被清空)  (重新捡)   (烧开)   (重新捡)   (消耗开门)
```

- 教学点 1：水会清空火 → 不要带着火穿水幕；
- 教学点 2：火能烧冰墙；
- 教学点 3：火用在门上就没了，所以最后一次拿火要留到门口；
- 坑底放火焰，掉下去回检查点；
- 不放移动平台（这一关只教元素）。

### 6.6 第 5 关「风之塔」（约 40 秒）

```
起点 ── 火种① ── 水幕（浇灭）── 火种② ── 风场（垂直托起）── 高台 ── 火盆门 ── 终点
```

- **风场**：站进去被持续往上托，到顶再往右落到高台；
- **水**：水幕清空火，逼玩家过了水再捡火；
- **火**：最后开终点门；
- 这一关是**竖向**的，和第 4 关的横向四重奏区分开，也是演示视频最好看的一段；
- 「关卡检查.bat」不模拟风场，这一关单独用真人试玩验收。

> 如果 D7 结束时第 5 关还不稳定，**直接砍掉第 5 关**，保留 4 关。
> 4 关 + 完整视频/文档，比 5 关 + 半成品更稳。

### 6.7 关卡设计红线（新关卡必须遵守）

1. **同高度平跳**：空隙 ≤ 100 最稳，工具上限约 146；
2. **要上升 30**：空隙 ≤ 90 最稳，工具上限约 134；
3. **要上升 60**：空隙 ≤ 75 最稳，工具上限约 118；
4. **上升 > 92**：跳不上去，必须拆成两级台阶或电梯；
5. **移动平台**：要么和地面**齐平**（走上去），要么**高过玩家头顶 64 像素**（能钻过去）；
   **绝对不要**让平台顶面落在“地面上方 0~64 像素”且和可走地面重叠——那是一堵墙；
6. **移动平台的行程**：`_add_moving_platform` 传的 `travel` 是**总行程**，
   实际在 `pos ± travel/2` 之间往返；
7. **每关至少 1 个检查点**，死亡惩罚别太重。

## 8. 参数调试指南（你试玩时改什么）

### 8.1 手感参数（`scripts/player.gd` 顶部）

| 参数 | 现在 | 作用 | 建议范围 |
|---|---|---|---|
| `speed` | 240 | 水平最大速度 | 200~280 |
| `jump_velocity` | -480 | 起跳速度（负=向上） | -420~-520 |
| `gravity` | 1250 | 上升重力 | 1000~1500 |
| `fall_gravity_mult` | 1.35 | 下落重力倍率 | 1.1~1.6 |
| `jump_cut_mult` | 0.45 | 松手砍掉多少上升速度 | 0.3~0.6 |
| `coyote_time` | 0.10 | 离开平台后还能跳的窗口 | 0.06~0.14 |
| `jump_buffer_time` | 0.12 | 落地前按跳的缓冲 | 0.08~0.16 |
| `air_accel_ratio` | 0.5 | 空中转向快慢 | 0.4~0.8 |
| `ground_accel_mult` | 15 | 地面加速倍数 | 10~20 |

**调试方法：**
1. 一次只改 **1 个**数字；
2. 改完 F5，玩第 1 关 1 分钟；
3. 觉得更差就改回去；
4. 每次改动在 `docs/测试记录.md` 写一行“改了什么 → 感觉如何”。

> 不要一次改 5 个参数——你会不知道是哪个起了作用。

### 8.2 关卡参数（`scripts/levels/level_*.gd`）

| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 平台位置 | `_add_platform(Vector2(x, y), 宽, 高)` | 顶面 = y − 高/2 |
| 空隙太大 | 把目标平台往左挪 / 把当前平台加宽 | 改完跑 `关卡检查.bat` |
| 移动平台行程 | `_add_moving_platform(pos, Vector2(行程, 0), 速度, 宽)` | 实际在 pos ± 行程/2 |
| 闪烁平台节奏 | `_add_blink_platform(pos, 宽, phase)` | phase 是 0~1 的相位 |
| 火焰范围 | `_add_flame_row(from_x, to_x, y, 步长)` | 火焰必须在坑底，不能放在可走地面 |

**改完必做：** 双击 `关卡检查.bat` → 看 `>>> OK`；再 F5 实玩那一段。
