## 0\. 核心

* **马里奥式**：跳坑、金币、史莱姆、移动平台、旗杆式终点。
* **元素**：火 / 水 / 冰 / 风 / 岩石；每关一个主题或两三个元素的组合。
* 操作不变：A/D 移动、空格跳、R 重开；死亡回检查点，整关机关复位
（**金币例外**：检查点之前吃到的会保留，见 5.2）。

## 2\. 逐关

### 第 1 关 · 绿色平原（马里奥 1-1）

* **想教**：跳坑、金币、史莱姆；没有任何元素，先把操作跑顺。
* **结构**：四段地面，三个 100 像素的坑；5 枚金币；3 只蓝色史莱姆；检查点在中间。
* **为什么**：第一关不塞机制，玩家只需要记住“空格跳、坑会死、金币能捡”。
* **验收**：三条命内到终点；金币至少吃到 3 枚。

### 第 2 关 · 水管与平台

* **想教**：移动平台；钥匙门。
* **结构**：两个 400 像素的大坑，各一块横向移动平台；最后 2300 拿钥匙、2600 开门、2800 终点。
* **为什么**：马里奥的“等平台”节奏；钥匙门第一次出现，告诉玩家“钥匙是必需道具”。
* **验收**：两次都能坐上平台；钥匙门能开。

### 第 3 关 · 火之花

* **想教**：火元素；火融冰墙；火盆开门；地火节奏。
* **结构**：火种 300 → 冰墙 800 → 地火 1200 → 火盆 1800 → 火门 2000 → 终点 2600。
* **为什么**：马里奥“火之花”的对应关；火有两个用途（融墙、点火盆），但都很直观。
* **验收**：能融墙、能闪地火、能开门。

### 第 4 关 · 冰之谷

* **想教**：冰桥、滑冰、短火焰、火融冰墙、钥匙门。
* **结构**：冰种 250 → 冻桥 400\~1000（600 宽）→ 短火焰 850（60 高）→ 火种 1200 → 冰墙 1300 → 钥匙 1700 → 钥匙门 2200 → 终点 2600。
* **为什么**：冰面最高速 348，滑到火焰和 100 坑前必须跳；冰与火在同一关各用一次。
* **验收**：能冻桥、能滑、能跳过短火焰和坑、能融墙、能开门。

### 第 5 关 · 风之丘

* **想教**：风区加速跳远；移动平台；火融冰墙。
* **结构**：两个 300 坑用移动平台；中间 130 坑借风区跳；火种 1400 → 冰墙 1600 → 钥匙 2100 → 门 2500 → 终点 2800。
* **为什么**：风不是把人吹起来，而是把最大速度临时提高，跳得更远；和马里奥的“加速跑”感觉接近。
* **验收**：两个平台都能坐；130 坑能借风跳过；火墙钥匙门能过。

### 第 6 关 · 岩石矿洞

* **想教**：岩石砸墙；岩石顶起石柱。
* **结构**：岩石球 300 → 石墙 900 → 石柱 1500 → 钥匙 2000 → 门 2400 → 终点 2800。
* **为什么**：岩石的两种用法一次教完；石柱是“从地里长出来的台阶”。
* **验收**：能砸墙、能升柱、能开门。

### 第 7 关 · 水之洞

* **想教**：水会浇灭火种；带着火跳过水幕。
* **结构**：火种 400 → 水幕 800 → 冰墙 1100 → 钥匙 1600 → 门 2000 → 终点 2800。
* **为什么**：水不是即死，而是“清掉你手里的火”；玩家要跳过去，而不是走进去。
* **验收**：火能保住到冰墙；水幕能跳过；钥匙门能开。

### 第 8 关 · 元素回廊

* **想教**：冰、岩、火、风四种元素在同一关各用一次。
* **结构**：冰种 250 → 冻桥 600 → 岩石 800 → 石墙 1000 → 火种 1200 → 冰墙 1400 → 风区 1600 → 钥匙 1900 → 门 2600 → 终点 3000。
* **为什么**：第 3\~7 关的单元素在这里合并；顺序明确，不会同时要求两种元素。
* **验收**：四种元素都能用上；钥匙门能开。

### 第 9 关 · 天空之城（两段风场 + 横跳）

* **想教**：风场把玩家托到高处；两段风场之间要自己横跳；高台边缘还有一股 40% 的弱风。
* **结构**：起点平台（顶面 1500）-100\~500 → 第一段风场 x 550\~680（y 1000\~1450）→ **100 像素缺口** → 第二段风场 x 780\~940（y 820\~1050）→ 高台 1000\~1300（顶面 880，左边缘内缩 50，缩进处是顶面 900 的台阶 + 40% 升力弱风场 x 940\~990）→ 地火 1350 → 带怪平台 1400\~1800 → 钥匙 1600 → 钥匙门 1680 → 终点 1750。
* **为什么**：原来是一根 300 宽的大风柱，站着不动就被托上去；拆成两段 + 缺口后，玩家必须在“升到顶”之后主动横跳，风场从“电梯”变成“需要操作的地形”。高台边缘的弱风场是给愿意贴边走的玩家的奖励（金币 + “原来边缘也能用”的发现）。
* **检查**：这一关是竖向风场，`关卡检查.bat` 的抛物线模型不适用，单独用真人试玩验收。
* **验收**：能被第一段托到 1000 附近、横跳过 100 缺口进第二段、落到高台；能拿到弱风口那枚金币；躲开地火和喷火史莱姆；开门到终点。
* **2026-10-28 调整（方案 9-1 / 9-2）**：

  * 单一风场（x 550\~850，300 宽）拆成两段：x 550\~680 与 x 780\~940，中间缺口正好 **100**。
  * 高台左边缘内缩 50（950→1000），缩进处加一级顶面 900 的台阶；台阶上是 **40% 升力（104 px/s）** 的弱风场，金币放在风场里。
  * 金币 5 → 6；提示牌改成“两段风场：升起来→横跳→再升”“台阶边有股弱风，金币在上面”。
  * !\[两段风场](screenshots/第九关-两段风场.png)

### 第 10 关 · 终章：元素城堡

* **想教**：五种元素 + 地火 + 史莱姆 + 喷火史莱姆的综合关；中段要“火 + 风”连着用。
* **结构**：冰种 250 → 冻桥 600 → 岩石 900 → 地火 1000 → 石墙 1100 → 火种 1400 → 冰墙 1600 → **上升风场 1640\~1780** → **钥匙 1710（高处 y=400）** → 水平风区 1830 → 地火 2200 → 门 2900 → 喷火史莱姆 3050 → 终点 3200。
* **为什么**：把前面所有机制串一遍；有检查点，死一次不用从头来。钥匙放在风场顶端，逼玩家把“火融冰墙”和“风场起飞”连成一次组合操作。
* **验收**：能走完整条链；五种元素至少各用一次；钥匙门能开。
* **2026-10-27 调整**：

  * 倒数第二块平台（2100\~2800）上的巡逻史莱姆撤掉 —— 这里是跳向最后一块平台和钥匙门的落点，怪占着容易被撞下去。
  * 喷火史莱姆 3000 → **3050**：离最后一块平台左边缘从 100 提到 150（×1.5），从 2800\~2900 的缝隙跳上来时有更宽的落地区。
  * 死亡区：5 块平台铺到 3400，原来死亡区只有 2400 宽（形状没生效），2900 之后掉下去不会死；已修，现在覆盖 -200\~3500。
* **2026-10-28 调整（方案 10-1）**：

  * 线性元素链改成**元素组合房间**：火种 1400 → 冰墙 1600（40×160，横在走廊上，跳不过去）→ 融墙后走进**上升风场**（x 1640\~1780，y 360\~780）→ 托到高处拿钥匙。
  * 钥匙从 (2400, 750) 挪到 **(1710, 400)**：不融墙进不去风场，不进风场够不到钥匙。
  * 水平风区从 1800 挪到 **1830**，避免和第 10 关新增的上升风场叠在一起。
  * !\[元素组合房间](screenshots/第十关-元素组合房间.png)

### 第 11 关 · 分岔

* **想教**：第一次选路；上层快而险（冰滑道 + 2 金币），下层稳而慢（史莱姆 + 2 金币）。
* **结构**：起点高台（顶 520）→ 跳过 100 缺口 → 上层平台 500\~950 → 河流/冰桥 950\~1400 → 落回下层 1300\~1800 → 火盆 1700 → 门 1900 → 终点 2250；下层 400\~1400 是史莱姆走廊。
* **为什么**：两条路都到汇合点，上层要冰元素冻桥、下层要躲史莱姆，“选哪条”本身就是内容。
* **2026-10-27 调整**：

  * 河流（水池/冰桥）300 → **450**（950\~1400，×1.5），左端不动，右端接到下层 1300\~1800 平台的正上方。
  * 1 倍处（旧右端 x=1250）加一个**地火**：挂在冰面 y=520 上，朝上喷、默认长 110；间歇节奏（灭 1.5s → 预警 0.4s → 着火 1s），要趁灭滑过去 —— 跳不过去（跳跃高度 92 < 110）。
  * 净空：冰桥底 540 → 下层地面 780 = 240，不撞头。
* **2026-10-28 调整（方案 11-1 的金币部分）**：

  * 上层金币 3 → **2**（全关 5 → 4），让两条路的奖励价值接近。
  * 方案里“踩灭史莱姆 / 掉落物点火盆”没有做：本作没有踩踏和掉落物机制，详见第 6 节。
* **验收**：两条路都能到汇合点；冰桥能冻；地火能掐时间过。

### 第 12 关 · 风车

* **想教**：风场竖井 + 上下升降台；上层可选钥匙 + 金币房。
* **结构**：下层 0\~1200（地火 800、史莱姆 600）→ 竖井升降台（1200，行程 ±90）→ 风场 → 上层 1300\~1900（钥匙 1400、钥匙门 1600、金币房 1800）→ 下层 1900\~2400（火盆 2200、门 2300）→ 终点 2400。
* **为什么**：把“等平台”和“风场托举”合在一起；钥匙是可选，走支路多拿金币。
* **验收**：升降台能坐；风场能托上上层；支路钥匙能拿；火盆门能开。

### 第 13 关 · 火雨

* **想教**：地火是固定节奏、天火由压力板触发；低天花板下的走位。
* **结构**：地面 100\~1700 + 1800\~2200 → 天花板 700\~1300 → 史莱姆 700 / 1200 → 压力板 750 + 天火 800（挂天花板底面）→ 钥匙 900 → 地火 1000 / 1300（y=780，周期 4 秒）→ 钥匙门 1600 → 火盆 1700 → 门 1900 → 终点 2100。
* **为什么**：地火是“数拍子”，天火是“看板子”——两种节奏叠在一起，不能只靠背板。
* **2026-10-27 调整**：

  * 上层平台（天花板）中心 660 → **630**：底面 680 → 650，离地净空 100 → **130**（×1.3）。
  * 天火 x=800 跟着从 680 → 650，长度 110 → 130，保持烧到地面 780，判定范围和原来一致（不会在脚下留缝）。
  * 可跳高度从 58 提到 88；工具仍报 WARN（净空 130 < 189），属于这一关“低天花板”的既定设计。
* **2026-10-28 调整（方案 13-1）**：

  * 天火 x=800 从固定周期改成**压力板触发**：踩下 x=750 的压力板 → **2 秒**后着火 → 烧 **1.5 秒** → 熄灭；离开压力板 **3 秒**后才重新待机（站着不动不会反复刷）。
  * 地火周期 2.9 → **4.0 秒**（灭 2.6 + 预警 0.4 + 着火 1.0），两个地火相位 0 / 0.5。
  * 说明：走廊是开放的，玩家可以跳过压力板、不触发天火 —— 目前把它当“可选的风险”；要做成必经机关需要收窄通道，待定。
  * !\[压力板触发天火](screenshots/第十三关-压力板天火.png)
* **验收**：地火能等到“灭”的窗口；天火能在踩板后 2 秒躲开；钥匙门能开；终点可达。

### 第 14 关 · 冰宫

## 5\. 2026-10-27 本轮修改记录

### 5.1 掉落死亡区：第 10 关“缝隙掉下去不死”（P0）

* **现象**：第 10 关最后两块平台（2100\~2800 / 2900\~3400）中间掉下去，玩家一直往下掉，不会死；相机停在边界上，看起来像卡死。
* **根因**：`scenes/world/death\\\\\\\_zone.tscn` 的 `CollisionShape2D` 本来没有 shape，形状是 `scripts/death\\\\\\\_zone.gd` 的 `\\\\\\\_ready()` 按 `zone\\\\\\\_size` 现建的。而 `level\\\\\\\_base.\\\\\\\_add\\\\\\\_death\\\\\\\_zone()` 以前写的是“先 `add\\\\\\\_child()`、再 `setup(size)`”——`add\\\\\\\_child()` 会**同步**触发 `\\\\\\\_ready()`，那一刻读到的还是默认值 2400，形状就永远定在 **2400×200、居中于关卡中点**。第 10 关宽 3400，最右边 550 像素（含整块最后平台）都是无底洞。14 关里 12 关都缺一截。
* **修法**：

  * `death\\\\\\\_zone.gd`：`setup()` 在已进树时也立刻重建形状；`\\\\\\\_ready()` 统一走 `\\\\\\\_apply\\\\\\\_size()`；场景里漏了 `CollisionShape2D` 会自己补一个，避免变成“没形状的摆设”。
  * `level\\\\\\\_base.\\\\\\\_add\\\\\\\_death\\\\\\\_zone()`：改成**先写 `zone\\\\\\\_size`、先摆位置，再 `add\\\\\\\_child()`**，从源头上不依赖调用顺序。
  * `tools/verify\\\\\\\_levels.gd` 新增 `\\\\\\\_check\\\\\\\_death\\\\\\\_zone()`：死亡区必须盖住本关所有落脚面的水平范围，否则直接 FAIL（`关卡检查.bat` 会报出来）。

### 5.2 金币改成「检查点存档」

* **规则**（解决“检查点前吃的金币，死一次就白吃”）：

|情况|复活后|
|-|-|
|检查点**之前**吃掉的|数量保留，地图上保持消失|
|检查点**之后**吃掉的|数量退回，金币重新出现在地图上|
|还没碰过检查点就死|归 0，全部重新出现（等于没有存档）|
|之后又碰到新检查点|快照更新为那一刻的进度|

* **实现**：

  * `scripts/collectibles/coin.gd`：加 `coin\\\\\\\_id`，以及 `is\\\\\\\_taken()` / `set\\\\\\\_taken\\\\\\\_state()`（静默设为已吃/未吃，不播音效、不加分）。
  * `scripts/level\\\\\\\_base.gd`：`\\\\\\\_on\\\\\\\_checkpoint\\\\\\\_reached()` 调 `\\\\\\\_snapshot\\\\\\\_coins()` 记下已吃金币编号；复活时 `\\\\\\\_reset\\\\\\\_hazards()` 先把金币全放回，再 `\\\\\\\_restore\\\\\\\_coins\\\\\\\_after\\\\\\\_respawn()` 把存档里那几枚重新藏掉，同时把 `GameState.coins` 恢复成存档数量（HUD 每帧读 `GameState.coins`，会自动对上）。
* **踩到的坑**：第一版复活后金币莫名 +1。原因是金币恢复监测的那一帧，物理服务器里玩家还停在**死亡位置**，死亡点那枚金币被立刻又“捡”了一次。现在 `\\\\\\\_respawn()` 先把玩家放回复活点、**等 2 个物理帧**同步完 transform 和碰撞形状，再复位机关。
* **范围**：只改了金币；钥匙、元素球仍然随复活重置。
